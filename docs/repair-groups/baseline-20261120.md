## Architecture and implementation boundaries

- Shared document UI: `lib/screens/jobs/job_document_screen.dart`.
- Edits/conversion: `offline_document_draft_service.dart`,
  `offline_document_edit_service.dart`, `offline_estimate_invoice_service.dart`.
- Drift SQLite baseline schema 22. Document snapshots use
  `local_document_details` with legacy preference recovery. Existing migrations
  include additive idempotent raw SQL schemas.
- New additive schema 23: repair groups, membership (one group per existing line),
  immutable authorization events/signature references and scope generations.
  Other Items is a projection, never a group row.
- Authorization selects saved priced lines; it does not create a pricing engine.
  Conversion must retain the complete source estimate, exclude unapproved lines,
  and retain numbering, job/task relationships and retry protections.
- Every saved estimate edit observes customer scope. Changed and reverted scope
  cannot revive an old approval. Unaffected groups can retain their approval.
- Legacy cloud conversion/merge must never copy unapproved source lines.
  Grouped conversion stays local; legacy server merge is fenced until a
  group-aware reconciliation contract exists. No production SQL is applied.

## LAN gap

Integrated `payroll_lan_*` provides device signatures, AES-GCM encryption,
paired enrollment, durable delivery and acknowledgments for payroll operations.
Those employee permissions and small-message limits are not customer review
permissions and cannot be reused as a kiosk transport. Kiosk document-scoped
sessions, kiosk enrollment, bounded photo transfer, signed-decision return and
customer-data clearing need a separate protocol. No cloud fallback is approved.

### Outstanding release gates

- Partial selection on an estimate with document-wide discounts is blocked.
  Current discount editing uses server RPCs; the local draft calculator skips
  discount rows while the saved-document calculator retains their saved amounts.
  A shared, verified local discount path must be completed before releasing this
  case. Do not invent a parallel pricing engine or silently reuse a full-estimate
  percentage discount after partial selection.
- Group metadata has no supported Supabase reconciliation contract yet. Grouped
  draft upload, edit replay and legacy server merge are fenced. This draft does
  not promise cross-device group synchronization. Existing server-side documents
  can still be stale on older devices; coordinated client rollout and the LAN
  document contract remain required before release.
- Kiosk enrollment, document-scoped delivery, durable signed return, acknowledgment,
  media transfer and customer clearing have not been implemented. Do not expose
  payroll endpoints or add a cloud fallback. Stage B remains separate.
- The invoice view labels inherited approved groups on its existing item rows;
  final grouped invoice presentation and full interaction validation remain.
- Full exact-head Diagnostics/Android/iOS verification and review against PR 487
  and Reports PR 488 are required. Do not merge or produce a production APK.
